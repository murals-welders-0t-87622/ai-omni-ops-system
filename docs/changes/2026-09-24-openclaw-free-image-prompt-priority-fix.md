# 2026-09-24 OpenClaw 自由生图主体与参考图优先级修复

> 后续诊断补充：本次 prompt 优先级调整记录的是较早一轮观察，不能作为 v8/v9 场景与服装不遵从的完整根因。2026-09-25 的 prompt-wire 运行日志显示，这几次调用在 MCP 入口的识别指令字段为空，用户 prompt 未进入 Provider 请求。最新结论与兼容映射见 `docs/changes/2026-09-25-openclaw-reference-forwarding-and-prompt-diagnostics.md`。

## 1. 变更背景

WorkBuddy 通过 MCP 调用多元探索 `gpt-image-2` 时，即使 prompt 明确要求新的主体和场景，结果仍反复保留参考图中的 Tennant T7 与仓库。运行结果确认 Provider、模型和参考图上传均成功，因此问题不在模型路由或参考图未传入。

## 2. 根因

`free_image` 模式会在用户 prompt 后追加“有参考图时优先继承主体特征”的系统要求。当用户要求更换主体时，这条附加要求与用户 prompt 冲突，并把参考图主体置于优先级更高的位置。

此外，自由生图虽然默认关闭完整品牌资料注入，原 prompt 仍会在首句无条件包含当前品牌名；品牌名若包含具体产品名，也可能给图像模型增加不需要的主体锚点。

## 3. 修改内容

- 用户文字明确要求更换参考图主体或场景时，以用户文字为准，参考图只用于构图、视角、光线、材质和风格参考。
- 仅当用户明确要求保留参考图主体时，才继承参考图主体特征。
- 默认未启用品牌资料注入时，不再把当前品牌名自动写入自由生图 prompt。
- 完整品牌资料显式注入时，仍可结合品牌名和品牌资料生成。
- 增加不含完整 prompt、图片内容或密钥的临时诊断字段，记录参考图、主体关键词及品牌上下文状态。

## 4. 影响范围

- 仅影响 OpenClaw `create_design_work` 的图片自由生图模式。
- 不改变 Provider / 模型选择、API 请求格式、图片存储或参考图上传链路。
- 不影响营销配图、视频故事板等其它提示词模式。
- 不改数据库结构和历史作品。

## 6. 后续注意

- 多元探索文档要求图像尺寸宽高为 16 的倍数；系统自由生图默认尺寸 `1242x1660` 与此约束不一致。本次先不混入主体遵循度修复，后续应单独验证并收口尺寸值。
- 图像模型对精确文字和复杂语义仍不保证完全遵循；需要精确排版的文字继续采用生成底图后程序合成。

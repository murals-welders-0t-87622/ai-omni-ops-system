# 2026-09-25 OpenClaw 自由生图参考图输入策略（已被纠正）

> 本文记录曾实施但方向错误的临时策略，不代表问题已修复。后续对照测试显示，参考图未发送时 prompt 仍然 0% 遵从，因此“参考图输入导致 prompt 失效”的判断不成立。最终根因是 MCP 调用的 `prompt` 字段未被入口识别；当前正确行为和 post-fix 证据见 `docs/changes/2026-09-25-openclaw-reference-forwarding-and-prompt-diagnostics.md`。

## 当时观察

`gpt-image-2` 使用 Tennant T7 参考图时，即使提示词要求三花猫、护士和医院走廊，生成结果仍会沿用工业清洁设备场景。上一轮只调整了提示词优先级，实测只能让主体部分响应，无法解除图像输入对场景和服装的绑定。

## 当时的推断（未被证实）

当时将参考图图像输入判断为场景锁定的原因，但后续测试发现即使参考图未发送，中文和英文 prompt 仍不能控制主体；因此该推断不是根因。

## 曾实施的策略（现已撤销）

- `create_design_work` 新增 `referenceImageMode`：
- 当时将 `prompt_only` 设为默认，导致用户提供的参考图默认不参与生图。
- 该行为已在 2026-09-25 更正：默认恢复参考图转发，只有显式 `prompt_only` 才忽略参考图。

## 后续证据与纠正

- 用户提供的 v5/v6 对照显示，参考图被确认接收但未发送时，中文与英文 anthropomorphic prompt 仍报告 0% 遵从。
- 这证明禁用参考图既不符合用户预期，也没有修复 prompt 遵从度。
- post-fix 脱敏日志确认：MCP 接收 `prompt` 后，主体/场景关键词进入服务端及 Provider 请求；参考图仍随请求发送。用户实测确认 prompt 生效，详见后续变更记录。

## 验证

- 此策略实施时构建通过，但真实测试反证了其修复目标。
- 曾实施的默认 `prompt_only` 策略已撤销；真实 post-fix MCP 调用和用户确认均通过。
